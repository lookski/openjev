## A 版 · 知乎回答体 (主推)

**标题建议: 怎么判断一条消息是不是阴阳怪气?我让本地大模型直接输出概率**

正文:

最近把一个自己折腾的小项目上线了,免费免安装,浏览器打开就能用:

**https://linrin0306-openjev-detector.static.hf.space**

粘贴一条微信/邮件/评论区消息,三秒钟给你三个判定:

1. **是不是阴阳怪气** (Yes/No + 概率)
2. **敌意程度** (0-3 级连续评分)
3. **真实语气** (真诚 / 被动攻击 / 纯讽刺)

比如这句职场经典阴阳:

> "哎呀,你们大厂做的这个产品真不错,我们小公司哪敢提意见呀,能用了就很好了,反正在你们眼里我们也不算什么重要客户。"

判定:阴阳怪气概率 **67.1%**,敌意 **1.57/3**(主档"明显不满,讽刺意味浓",概率 69.7%),语气分类"真诚"占 79.2% —— **一边说"真不错",一边被模型读出 69.7% 的讽刺浓度**,这个自相矛盾恰恰是原始概率比单一标签有价值的地方。

而一句正常的、稍微带点情绪的直球吐槽:

> "这个需求改了八遍了还没完,到底想怎么样?能不能一次说清楚再动手,我很累了。"

阴阳概率 **58.8%** —— 比上面那句真阴阳还高。模型对"直球抱怨"和"阴阳怪气"的分辨并不完美(敌意评分倒是分得开:直球 1.21 vs 阴阳 1.57),这个不完美我们不做遮掩,详见下文"原理"。

### 它的原理有点意思

市面上的"AI 判断语气"都是让大模型**生成一段话**再解析。生成又慢又会幻觉,解析还可能出错。

OpenJev 完全不生成文本。它对 Qwen3-0.6B 做一次前向传播,然后**直接读第一个答案位置的原始 logit**:把 "Yes/No" 或 "0/1/2/3" 这些答案 token 的概率挖出来做 softmax —— 概率是模型自己"想"的,不是被 prompt 出来的,也没有解析环节。类型错误在数学上不可能发生。

这也是 Jev(今年 9 月爆火的那家"决策模型")的思路。区别是 Jev 是闭源云服务($0.042/百万输入 token),OpenJev 用同一个思路把开源小模型变成本地决策引擎 —— **$0,离线,数据不出机器**。

### 技术栈(给想自己搭的人)

- Python 本地版:`pip install -e .`,支持 Qwen/Llama/Phi 等任何开源小模型
- 浏览器版(本次上线):transformers.js + ONNX 量化权重,推理全程在你设备上跑,**消息不上传任何服务器**;有 WebGPU 自动走高精度 fp16 档(与 Python 参考实现概率最大误差 0.0032),没有就自动切 WASM 快速档
- 全部开源:GitHub 搜 lookski/openjev

局限性也说实话:绝对数值对 prompt 措辞敏感;小模型对"直球 vs 阴阳"的分辨有误差(上面的例子就是证据);中文场景没有专门校准。它是个玩具级工具 + 一个认真的技术演示,不是商业级内容审核。

## C 版 · 技术社区(V2EX / 掘金 / 少数派)

**标题:OpenJev: 把本地 LLM 变成决策引擎 —— 不生成文本,直接读 logits 的掩码 softmax,顺手做了个阴阳怪气检测器(已上线在线 Demo)**

主链接:https://github.com/lookski/openjev
在线玩:https://linrin0306-openjev-detector.static.hf.space

核心机制:Jev 证明了"决策模型"这个范式 —— 发送状态 + 类型化问题,返回类型安全答案 + 校准概率。OpenJev 把它搬到本地:一次前向传播,掩码答案 token 的 logits,softmax 出原始概率。没有文本生成、没有采样、没有解析层。

三种原语,覆盖 90% 决策场景:
- `noul`:二选一(Yes/No),输出两 token 概率
- `score`:N 级评分,输出分布 + 期望值(如敌意 0-3 级)
- `choice`:N 选 1(如语气:真诚/被动攻击/纯讽刺)

浏览器版是 Python 引擎的 1:1 JS 移植:
- prompt 构建逐字节一致(Qwen3 chat template,enable_thinking=false 空思考块)
- 掩码 softmax 结果与本地 torch fp32 参考比对:fp16 档最大绝对误差 0.0032,ALL-PASS;量化档(q4/int8)概率分布失真,已识别为不可用路线并写进文档
- WebGPU 优先,wasm 回退;onnxruntime-web jsep 运行时自托管,无 CDN 依赖
- 踩过的坑都记录在仓库 docs/(Static Space 1GB 限额、fp16 在 wasm32 上 bad_alloc、jsep 无 GPU 时不自动回退等)

对这种"概率透明"的用法有个观察:原始概率会诚实地暴露模型的自相矛盾 —— 阴阳概率 67% 的同时语气分类 79% 说真诚。这种矛盾在生成式方案里会被"解析出的单一答案"掩盖掉。

开源 MIT,模型任意换(Qwen/Llama/Phi),pip install -e . 五分钟本地跑起来。欢迎来踩。
