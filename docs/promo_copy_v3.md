# 怎么判断一条消息是不是阴阳怪气?我让本地大模型直接输出概率

最近把一个自己折腾的小项目上线了,免费免安装,浏览器打开就能用:

**https://linrin0306-openjev-detector.static.hf.space**

粘贴一条微信/邮件/评论区消息,三秒钟给你三个判定:

1. **是不是阴阳怪气** (Yes/No + 概率)
2. **敌意程度** (0-3 级连续评分)
3. **真实语气** (真诚 / 被动攻击 / 纯讽刺)

比如这句职场经典阴阳:

> "哎呀,你们大厂做的这个产品真不错,我们小公司哪敢提意见呀,能用了就很好了,反正在你们眼里我们也不算什么重要客户。"

判定:阴阳怪气概率 **67.1%**,敌意 **1.57/3**(主档"明显不满,讽刺意味浓",概率 69.7%),语气分类"真诚"占 79.2% —— **一边说"真不错",一边被模型读出 69.7% 的讽刺浓度**,这个自相矛盾恰恰是原始概率比单一标签有价值的地方。

而一句正常的、稍微带点情绪的直球吐槽:

> "这个需求改了八遍了还没完,到底想怎么样?能不能一次说清楚再动手,我很累了。"

阴阳概率 **58.8%** —— 比上面那句真阴阳还高。模型对"直球抱怨"和"阴阳怪气"的分辨并不完美(敌意评分倒是分得开:直球 1.21 vs 阴阳 1.57),这个不完美我们不做遮掩,详见下文"原理"。

### 它的原理有点意思

市面上的"AI 判断语气"都是让大模型**生成一段话**再解析。生成又慢又会幻觉,解析还可能出错。

OpenJev 完全不生成文本。它对 Qwen3-0.6B 做一次前向传播,然后**直接读第一个答案位置的原始 logit**:把 "Yes/No" 或 "0/1/2/3" 这些答案 token 的概率挖出来做 softmax —— 概率是模型自己"想"的,不是被 prompt 出来的,也没有解析环节。类型错误在数学上不可能发生。

这也是 Jev(今年 9 月爆火的那家"决策模型")的思路。区别是 Jev 是闭源云服务($0.042/百万输入 token),OpenJev 用同一个思路把开源小模型变成本地决策引擎 —— **$0,离线,数据不出机器**。

### 这两周它长成了一个"追人雷达"

检测器只是开始。这两个星期我把同一套"原始概率输出"引擎,接到了真实的聊天场景上——现在它是一个跨平台的聊天分析助手:

**微信**:截图(或 Ctrl+F2 框选文字)丢给悬浮窗,OCR 识别后给出判定;`wxauto` 思路的桌面助手能盯指定会话,新消息自动生成分析,**草稿直接回填到输入框**(默认绝不自动发送,风险自担的开关才有)。

**QQ**:OneBot 11 协议(NapCat),双向历史完整还原——包括你自己发的消息;更骚的是**半透明分析卡片直接浮在聊天窗口上**,新消息一到,判定和"下一步建议"就地生成,点一下复制建议。全程不碰 QQ 进程,纯屏幕空间覆盖。

**Telegram**:最干净的一个。官方 MTProto 用户 API,零注入,还能**回填历史消息**(`--backfill 200` 直接把最近两百条喂进上下文再分析)——这是 QQ 和微信都做不到的。

**WhatsApp Web**:Playwright 驱动,持久 profile 首次扫码后免登录,轮询消息 DOM 还原说话人。实验性质——WhatsApp 的 ToS 不支持第三方自动化,DOM 也可能随版本变,写了多级选择器回退,`--selftest` 可以不开浏览器验证全链路。

**任意平台兜底**:本地起一个 hub(网页面板 + 手机适配 + SSE 实时推送流),任何聊天里复制粘贴对方的话,三秒出判定;判定实时推到手机页面。

每个平台的输出都不只是"冲/稳/缓/停"四档判定,还有两个新东西:

- **回复方向**:一句话策略,比如"接梗+抛二选一时间"——告诉你这步棋该往哪走;
- **下一步建议**:直接可粘贴的回复草稿,点一下就进剪贴板。

### 依然不生成文本来做判断

判定引擎的原理没变:不生成、不解析、直接读概率。变的只是接入方式——从"你粘贴它分析"变成"它看着聊天自己分析,你决定发什么"。

所有自动发送默认关闭。雷达是雷达,扳机在你手里。

### 技术栈(给想自己搭的人)

- Python 本地版:`pip install -e .`,支持 Qwen/Llama/Phi 等任何开源小模型
- 浏览器版:transformers.js + ONNX 量化权重,推理全程在你设备上跑,**消息不上传任何服务器**;有 WebGPU 自动走高精度 fp16 档(与 Python 参考实现概率最大误差 0.0032),没有就自动切 WASM 快速档
- 全平台助手代码 + 诚实风险对照表(哪个平台用什么协议、哪个有封号风险、哪个根本没路)全部开源:GitHub 搜 lookski/openjev

局限性也说实话:绝对数值对 prompt 措辞敏感;小模型对"直球 vs 阴阳"的分辨有误差(上面的例子就是证据);中文场景没有专门校准;聊天助手的平台接入各有不同的稳定性与风险等级(README 里有逐平台诚实说明)。它是个玩具级工具 + 一个认真的技术演示,不是商业级内容审核。
